# Round 2 · Lens 6 — Performance & build

_09/10/2026 · read-only review. IDs are numbered across the whole round-2 report._

## Verdict
**Fail (pending measurement)** — 1 Important · likely (I21) and 4 Minor (M36–M39). Nothing blocks release by itself; I21 should be timed with Instruments on the oldest supported iPhone before deciding. The biggest user-visible effect found by this lens — Today's check-in answer lost on every `reload()` — is a correctness bug and is listed as **I3 in lens 1**.

## Findings

### Important
I21 [Perf] [Important · likely] iOS/App/Features/Today/TodayView.swift:38-46,62-63 (+ iOS/App/Features/Today/TodayModel.swift:304,390,431-433,444,495) — one evaluation of `TodayView.body` builds about 22 full session plans and does ~226 bundle lookups · `session` is a computed property calling `minutes(of:)` → `request.plan(content:)` and is read 6 times per body (directly and through `sessionDetail`, `goalLine`, `checkInNote`, the check-in condition, `swapOptions`); `goalLine` adds 1 build, `swapOptions` 3, and `extras` is read twice (L62 `isEmpty`, L63), each read doing 3 `minutes(of:)` + 3 `SessionVideo.has` → `plan` (12 builds) and `SessionVideo.filmed` (up to 113 `Bundle.main.url`, AllSessionsModel.swift:63-75); each build creates a `VoiceRotation.Table` over all 682 voice lines (SessionBuilder.swift:55, VoiceRotation.swift:39-49) plus a second 682-entry dictionary and rotates 78–113 cues · body runs on every check-in tap, every reload (new model instance) and every `store.offers` change: estimated 15–45 ms main-thread per body on an A12/A13 iPhone (XS/XR/SE 2, common in a 58–75 audience) → a dropped frame or two on the Achy/Okay/Great tap, repeated 5–6 times in the first seconds after launch · contradicts the model's own contract ("Works everything out once from `TodayInput`", TodayModel.swift:156) · fix: compute `request`, `session`, minutes, `goalLine`, `swapOptions`, `extras` once in `init` and again in `checkIn(_:)` (stored `private(set)`); cache `SessionVideo.filmed` per content bundle; build `VoiceRotation.Table` and the lines dictionary once per `ContentBundle`; then measure with Instruments' SwiftUI template ("Long View Body Updates"). Same pattern, smaller: `WorkoutPreviewModel.plan` is computed and built 3× per preview render (WorkoutPreviewModel.swift:80).
    Evidence: static count of plan builds per body (6 + 1 + 3 + 12); 682-line tables per build.

### Minor
M36 [Perf] [Minor · likely] iOS/App/Features/Root/AppModel.swift:148-157,175-224 (+ iOS/App/Features/Root/AppModel+StageRecap.swift:25-28) — `reload()` is a full rebuild for any small change and launch runs it 4–5 times · ~9 SwiftData fetches incl. all `WorkoutRecord`s unfiltered (:179), `ProgressSnapshot`, `ProgramRecapSnapshot`, a new `TodayModel`; `ProgramRecapSnapshot.init` calls `StageRecaps.stages` 4 times (directly, then inside `round`, `journeyStages`, `turnCard`), each filtering all sessions per stage through `ProgramCalendar.week` (StageRecaps.swift:19) → ~4–8k Calendar calls per reload at week 12 with N ≈ 84–168 sessions (~5–30 ms); every reload hands out a fresh `TodayModel`, so every tab root reading `app.today` re-renders (MainTabView.swift:80,130,148; ProgramView.swift:31), e.g. each Everyday-win tap re-renders Progress with its charts; during a trial every `apply()` also starts a full notification reschedule (StoreService.swift:175 → NotificationScheduler.swift:165-167) · fix: compute `stages` once and derive `round`/`journeyStages`/`turnCard` from it; call `onUpdate`/`reload` only when `apply()` changed something; drop the duplicate reload at :155 or :157; reschedule the trial reminder only when its date changes; keep the old `TodayModel` when `TodayInput` is equal (also fixes I3).

M37 [Perf] [Minor · likely] iOS/App/Services/Content/AppLanguage.swift:67-80 (read at iOS/App/Features/Me/MeSections.swift:323,325) — in **Release** builds `AppLanguage.selectable` is a computed `static var` that reads and JSON-decodes `content.vi.json` (646 KB, 682 lines with 6,988 timed words) on each access, twice per body of Me → Language and units; the section re-renders on open, on each language tap and on each Distance/Weight/Height tap (units `didSet` → full `reload()`, AppModel.swift:48-53) · ~30–80 ms per tap on an older iPhone; Debug returns `allCases`, so the owner's runs and captures never show it · fix: `static let selectable` (once per launch), or only check that the recordings exist.

M38 [Perf] [Minor · likely] iOS/App/Features/Workout/Shared/VideoLoopView.swift:233-252 — the still-frame cache only grows: a plain `[URL: UIImage]` of decoded 1280×720 frames (~3.7 MB each), no limit, no memory-warning purge · one walk day (7 moves × easy/quick) ~45–55 MB, all 83 clips in one process ~300 MB, held while the screen is locked during a walk (background audio) → likelier jetsam on 3 GB iPhones; on first show the prefetch (:45) and `StillFrameView`'s task (:227) both miss and generate the same frame twice · fix: `NSCache` with `totalCostLimit` (~40 MB) or keep current + next clip only; purge at session end and on memory warning; share in-flight requests per URL.

M39 [Perf] [Minor · likely] iOS/App/Features/Root/AppModel.swift:151 — on each cold launch a paying subscriber's Today is first built as the free plan: the first `reload()` runs before any customer record is applied (`StoreService.entitlement` starts `.free`, StoreService.swift:35) and the first frame renders while launch awaits `backend.customer()` (:154) · for one or a few frames: free rest days, locked extras, and for a subscriber who began with a trial (`lastTrialEnds` in the past, AppModel.swift:280-287) "Free walk of the day · N min" and possibly "Your trial has ended · See Pro plans" · Debug captures pin `entitlementOverride`, so they never show it · fix: read RevenueCat's cache first (`customerInfo(fetchPolicy: .fromCacheOnly)`, fast and offline), then reload once.

## Checked and OK
- RevenueCat configured once (`Purchases.isConfigured` guard), `.error` log level in Release; the update stream started once and cancelled on termination; no polling; the paywall reuses loaded offers and refetches only when empty, on Try again, or past the cache after a plan-unavailable error.
- Session audio (`SessionAudioComposer.compose`, nonisolated async) built off the main actor with an asset cache; the `.preparing` cover shows meanwhile.
- Players: clock ticks at 4 Hz (PlaybackEngine.swift:61); caption/countdown writes skipped when unchanged; motion at 50 Hz writes only `Int`/`Bool` (relies on Observation skipping equal values — verify on the Xcode 27 toolchain); `VideoLoopView.updateUIView` no-op for the same URL; confetti stops after 2.3 s; breathing guide pauses when inactive.
- Art sizes small: scenes ≤ 758×503, postcards/covers ~500×500, trees 322–376×696, figures ≤ 589×920; stage-strip thumbs (56×44 pt) decode 500 px JPGs — negligible.
- Bundle matches content: all 83 mp4 used; EN voice 682 files = 682 lines; VI 682 = 682; no stray media.
- Build: no Debug settings leaking into Release (XcodeGen Release presets, WMO, -O; Shared.xcconfig sets only the RevenueCat key); `en-US.json` fixtures, `.npz` and `.storekit` excluded from Release; every `App/Debug/*.swift` in `#if DEBUG`.
- Location `.fitness`, 5 m filter, background updates only during an outdoor walk. `sceneBecameActive` rebuilds only on a new day. All sessions builds its model once per appearance in `.task`. Stable `ForEach` ids in the hot views.
